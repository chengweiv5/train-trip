# 车次整卡选择设计

状态：用户已确认。基于 `origin/main` 的紧凑车次卡片改动，沿用日期单行横向滚动及已有布局。

## 目标与交互

选择只用于临时标记意向车次，购票仍在铁路12306 App 内进行。取消独立席别选择，席别仅展示符合当前查询条件的余票。

- 点击车次号、日期、时间、站点、余票文字或卡片空白处，选中该车次。每次仅选一个；再次点击已选卡片保持选中，点击其他卡片切换。
- 使用浅绿背景、深绿描边和“已选择”文字表达卡片选中。辅助服务把整卡识别为可选车次；席别没有独立按钮、单选或选中语义。
- “更多席别与余票”是唯一独立子操作，打开现有详情弹窗，不改变当前选中车次、不触发卡片点击。关闭后恢复原状态。
- 席别保留文字与余票值，用轻量信息标签展示，取消按钮边框、勾选和深绿选中填色；点击其区域仍由整卡响应。查询条件中的席别筛选不变。
- 底部仅在有选中车次时展示摘要：日期与车次、出发站及时间、到达站及时间（含跨日）、成人数量；不显示“选中的席别”。未选择时省略摘要。
- “打开 12306 App”始终可点击，包括未选择、无匹配结果和刷新期间；不强制选择、不触发查询、不写剪贴板、不自动打开官网。

## 状态与边界

- 状态仅保存 `selectedTripKey`，删除 `selectedSeat`。`select(trip: Trip)` 负责标记；`clearSelection()` 负责清除。
- 日期或到达站筛选隐藏当前车次时清除标记；排序、页面恢复及从 12306 返回时保留现有标记与滚动位置。保持现有离开城市页面时清除标记的规则，不新增持久收藏。
- 成功刷新的查询项若包含已选车次，按整车次是否仍符合当前查询条件判断：任一允许席别仍满足人数就保留；车次消失或不再满足条件则清除并提示“所选车次已不符合当前条件，请重新选择”。不得因原先点过的某个席别无票就清除仍符合条件的车次。
- 刷新失败或取消保持旧车次、原始查询时间与标记。
- 未安装或唤起失败时，无选择分别提示“未安装铁路12306\n安装后重试”“暂时无法打开 12306 App\n请稍后重试”；已有选择时继续说明“已选车次会保留”。

## 实现边界

`AppViewModel` 管理整车次选择与刷新失效；`DetailScreen` 负责卡片选择语义和独立余票详情入口；`DetailActions` 负责非交互席别信息、可选摘要和始终可用的主按钮。`RailwayAppLauncher` 原生启动逻辑不变，不增加深链或预填承诺。版本保持 0.4.0 / code 8。

## 验证

- 触摸车次号、时间、站点、余票与空白区域均选中卡片；一次仅一张，重复点击保持选中。
- 更多席别按钮在未选择及已选其他车次时均不改变选择；弹窗可达、关闭后恢复。
- 无选择时可真实调用注入的 App 启动器；未安装和失败提示不虚构已有选择；已有选择时保留。
- 单个席别失去余票但其他允许席别有票时保留车次；全部不符合或消失时清除；失败和取消保留。
