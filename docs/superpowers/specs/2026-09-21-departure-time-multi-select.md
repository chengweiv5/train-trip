# 出发时段快捷多选

用户要求出发时段可多选，并确认自定义保留一个连续区间，应用后替换快捷选择；取消自定义保留原多选。

## 交互

沿用v0.6.0 B4按钮行：全天、凌晨、早上、下午、晚上。四个快捷段分别是北京时间[00:00,06:00)、[06:00,12:00)、[12:00,18:00)、[18:00,24:00)。标题增加“可多选”提示；选中段可再次取消，按钮使用checkbox语义及现有浅蓝选中色。“全天”是独立重置操作，选择后只有全天高亮；从全天点某一段变为仅该段；取消最后一段或凑齐四段归一为全天。

早上+晚上只匹配两个区间的并集，下午不会被包含。下方显示按时间排序的实际范围，可自然换行；结果摘要显示“早上、晚上”。范围对所选日期逐日适用，不增加查询请求或重复车次。

自定义仍是原来的开始/结束滚轮、跨午夜规则与单次完成。已有单段/自定义保留原值；从多选进入时以最早选中段作为初始区间，显示“完成后将替换已选快捷时段”，避免把不连续的多选误显示为一个大区间。仅点完成调用替换；取消、返回不改变原值。完成后快捷选择被清除（若区间恰好等于某个快捷段则高亮该段），全天区间仍显示全天。

## 模型与持久化

新增核心枚举DeparturePeriod：EARLY/MORNING/AFTERNOON/EVENING，携带中文label和起止分钟。SearchFilters末尾追加departurePeriods:Set<DeparturePeriod>=emptySet()，保留现有startMinute/endMinute及位置参数兼容。非空集合优先决定过滤范围；空集合沿用单段逻辑。切换/重置通过核心方法统一处理：withDeparturePeriods、toggleDeparturePeriod、withCustomTime。isAllDay与selectedDeparturePeriods提供UI回显（旧版精确快捷单段也能选中）。

派生显示与持久化序列按开始时间排序。withDeparturePeriods中，空集合或四项归一到start=0/end=1440且集合为空；其他集合保留所选项，同时将start/end设为最早选中的一段，供自定义初始值和旧版本回退使用。withCustomTime设置start/end并清空集合。acceptsTime只接受0..1439；多选按任一区间命中，原单段仍为左闭右开、跨午夜分两边；校验只验证实际使用的时间模式。

Preferences增加periods数组（稳定枚举名、按时间排序），继续保存from/to。没有periods字段时保持旧版单段和其余筛选；有效集合恢复为多选。新字段格式错误或含未知项时整体回退现有from/to，避免部分解析擅自改变选择，并保留人数、席别、城市等其它有效条件。空数组代表单段；四项归一到全天。无新依赖或私有数据格式迁移脚本。

首页与单城查询共用FiltersScreen。原AppViewModel的单城草稿隔离、应用筛选快照、刷新/重试保持不变，新增字段通过copy自然传递。聚合仍调用acceptsTime，不按时段重新查询。
