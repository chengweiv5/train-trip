## 目标

用户填写候补人数后，提前筛出按当前人数可以继续提交候补的车次，减少在 12306 添加乘客后才遇到“所选车次候补人数过多”的无效操作。

必须区分三个事实：查询页显示“支持候补”、本次提交条件校验通过、候补订单已创建。只有第二个事实属于本功能结果；本次设计不创建订单、不支付，也不把校验通过表述为候补成功或保证出票。

## 技术前提与证据

当前 `TicketParser.kt` 只读取车次候补标记和席别原始票态；`Trip.confirmed()` 会将候补排除在有票城市结果外。现有匿名查询没有人数相关的候补提交校验。

尚未验证 12306 是否存在仅凭人数即可可靠判断的无副作用校验能力。开发前需要明确：校验是否要求登录、是否依赖真实乘客及资格、哪个阶段会真正创建订单、拒绝原因如何区分、官方可接受的人数范围和请求频率。没有证据时，不能根据候补标记、HTTP 成功或相邻人数的结果推断“可提交”。本轮不请求真实票务接口、不采集账号或乘客数据。

若只能验证容量，产品必须改称“人数容量校验通过”，不能承诺完整订单可提交；若必须带真实乘客才能验证，则“只填写人数”不足以实现完整目标，应先反馈可达边界。设计中的登录状态为条件分支，不代表已确认必须登录或已有登录实现。

## 入口与页面

延续 v1.0 品牌“有票再出发”、晴空蓝主题和 Android 原有导航。底部从“查票 / 想去”扩展为“查票 / 候补 / 想去”，候补为独立查询模式，保留查票和想去的原有状态。

1. **填写条件**：出发地、目的地、单个出发日期、出发时段、候补人数、席别。人数默认 1；示例为 2。人数支持减号、数字输入和加号；只接受正整数，上限遵循实测能力，不沿用普通查询 1–20 的上限。候补人数始终显示在主操作前。席别可多选，逐席别校验，不把不同席别人数相加。日期范围沿用官方起售能力，不硬编码固定天数。v2.0 首稿聚焦单日、单个目的地城市；同城各站由选择器明确，并在结果中显示准确区间。
2. **探测中**：先获取候补候选，再逐项校验。候选数量未知阶段不展示虚构百分比；确定计划后展示“已完成 X / Y 项”、通过/不可提交/未确认数。计数项为日期、车次、区间、席别的组合。可停止，已完成结果保留，未开始项显示“未探测”。
3. **结果列表**：固定展示条件摘要、探测时间、三类计数和筛选。默认“全部”，通过项优先；可筛“校验通过 / 不可提交 / 未确认”。卡片显示实际出发与到达站、日期、时刻、席别、人数、结果和更新时间。卡片结果是单个组合；同一车次不同席别独立。
4. **通过详情**：给出本次条件、已校验席别、通过时间，明确“提交条件通过 ≠ 候补兑现”。主按钮“打开 12306 App”；打开前刷新本项校验。刷新后不再通过时，先更新结果，由用户查看；不得继续展示旧成功。App 中仍需填写条件、选择乘客和提交，不暗示已自动带入。
5. **不可提交详情**：显示可归因的拒绝原因和时间；例“当前候补人数过多”。不虚构剩余名额或建议偷偷减少人数下单。可换车次、改席别或手动重新探测。
6. **未确认 / 暂停**：网络失败、服务限制、未知响应、登录需要、校验能力不足等均不归入不可提交。条件性登录提示仅在服务明确要求后出现，保留已完成结果；验证完成后仅重试未完成项。若账号改变，先使账号相关旧结果失效。
7. **条件变化 / 过期**：人数由 2 改为 3 后保留旧记录参考，但清除绿色通过态及可操作选择，主按钮变为“按 3 人重新探测”。显示旧人数和旧时间，绝不把 2 人结果复用为 3 人结果。

## 状态与结果规则

| 状态 | 判定证据 | 用户文案 | 操作 |
| --- | --- | --- | --- |
| 未探测 | 未开始，不存在校验响应 | 尚未探测 | 开始探测 |
| 探测中 | 当前组合请求进行中 | 正在校验 2 人候补条件 | 停止探测 |
| 通过 | 已证实的无副作用校验明确通过 | 本次校验通过 · 2 人 | 查看详情 / 刷新后打开 App |
| 拒绝 | 明确的业务拒绝码或响应 | 当前不可提交 | 查看原因 / 重新探测 |
| 未确认 | 无响应、异常、未知协议或证据不足 | 暂时无法确认 | 按原因重试或验证 |
| 未起售 / 不支持 | 明确来源状态，不属于候选 | 尚未起售 / 本席别不支持候补 | 更换日期或席别 |
| 已过期 | 本地新鲜度策略到期，或条件改变 | 结果需更新 | 重新探测 |
| 已停止 | 用户停止，未完成项不作判定 | 已停止，保留已完成结果 | 继续未完成项 |

“已过期”阈值属于后续实现参数，由接口验证后确定；设计不宣称任何时长内绝对可靠。全部未确认时显示“本次未能完成校验”，不能显示“没有可候补车次”。完整探测后零通过时，应显示零通过及拒绝/未确认分布；没有候选与全部被拒绝是不同空状态。

结果绑定：出发日期（乘客上车日期）、列车内部标识、实际出发/到达站、席别、人数，以及接口实际需要的账号/乘客上下文。列车代码不能单独作为缓存键。每项保留来源时间和最后校验时间；异步旧请求不得覆盖修改后的新条件。取消后迟到结果不更新当前会话。

限流、验证码或风控提示出现时暂停后续请求，不自动连续重试；不设计高频轮询或后台抢占。单项网络失败可以重试，批量操作仅重试未确认项；候补业务拒绝不等于网络异常。

## 视觉与交互约束

- 主色 `#0073AA`；页头 `#DDF2FF`；卡片 `#EAF5FC`；主文字 `#1E3443`；辅助文字 `#516774`。使用原有 12dp 卡片圆角、16dp 内容边距。
- 成功 `#0F7952` / `#EAF7F0`；拒绝 `#A8500C` / `#FFF4E5`；未确认与过期使用中性样式。状态同时包含图标和文字。
- 主要按钮高至少 48dp；数字输入、加减、导航和筛选点击区域至少 48dp；说明文字至少 12sp。短屏自然滚动，底部操作避开系统手势区。
- 320dp 或大字时：筛选横向滚动，卡片头尾换行，时间区必要时改纵向；条件摘要换行；不截断人数或拒绝原因。设计展开页不等同真机适配验证。
- 本轮以晴空蓝展示。实现继续使用现有四套主题角色，成功/拒绝语义色不随主题变化。
