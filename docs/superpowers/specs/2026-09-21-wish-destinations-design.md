# 查询目的地的想去快捷分组

用户提出在省份列表最前面增加“想去”，选择后右侧列出已收藏城市。保留已确认B4布局，以同一城市选择草稿提供快捷入口。

## 交互

普通宽度左列顶部固定“想去”，下面保持真实省份的可滚动列表；窄屏或大字体保留原省份下拉，“想去”为首项。进入页面仍恢复原浏览分组或默认已选城市所属省份，用户点击想去进入；浏览位置/分组随页面状态恢复。想去不是行政省份，不参与底部已选省级地区计数，也不加入核心行政目录。

右侧按最近收藏优先显示想去城市，同一cityId去重；行内显示城市名与真实省份。支持单选切换、全选/取消全选本组，沿用既有cityId草稿，切换省份和想去时勾选同步、无重复。全选仅操作当前可查询且不是出发城市的收藏，保留组外选择；当前出发城市/无站城市显示禁用原因，未收录收藏仍用保存的名称和省份显示但不可选。勾选只改变查询范围，不增删收藏；完成保存、取消不写回。

已有搜索仍搜索全目录，已选视图仍按真实省份分组；清空搜索/返回继续选择恢复正在浏览的分组。“恢复默认”“清空选择”保留当前行为。

无收藏时显示“还没有想去的城市”“可在首页的「想去」中添加城市”，不跳转破坏当前草稿。首次读取显示正在读取，不提前显示空状态；读取失败显示错误和“重新读取”。有旧数据且刷新中可显示旧列表与加载提示，加载/错误期间禁止本组全选和行修改，避免基于过期列表改选。普通省份继续可选。

## 数据和实现

TrainTripApp已持有WishlistViewModel；将其WishlistState和reload回调经FiltersScreen传入DestinationSelector，新增参数放末尾保留旧调用兼容。打开选择器调用reload，不创建独立存储实例，也不联网。响应同一ViewModel的收藏更新，不修改已选择的查询城市集合。内部常量WISH_DESTINATION_GROUP="wishlist"仅作为DestinationBrowserState.provinceId和列表状态键。

复用DestinationCityRow，增加可选showProvince；新增想去分组标题/状态/未收录行。原有省份与城市列表、搜索、底部完成和验证规则保持不变，Preferences和核心模型不改。
