# DeepSeek 按需目的地介绍

用户已选择 DeepSeek 并授权使用个人 API Key，目标是无自建服务、无人工维护云端城市库，首次打开新城市时自动整理并缓存。默认模型的产品名为 DeepSeek V4.1 Flash；官方模型列表实测返回 `deepseek-flash`、`deepseek-v4-pro`，因此 API 默认使用 `deepseek-flash`。密钥不进入源码、APK、测试样例、日志或文档。

## 已确认链路

手机直接读取携程公开城市页，从页面自带的城市目录解析名称与 URL；进入城市页后核验名称、省份和国内标记，不按拼音猜城市 ID。读取页面内嵌 `__NEXT_DATA__` 的城市与景点、餐馆数据，再有限获取景点／餐馆介绍。首版只支持已验证的携程来源，不宣称支持小红书、马蜂窝或 B站。禁止绕过登录、验证码、付费或证书检查。

DeepSeek 官方 Responses API 明确忽略 `web_search`，所以不假设模型联网。手机将实际获取的资料传给官方 `https://api.deepseek.com/chat/completions`，使用 JSON 输出、非思考模式和有限输出长度。模型只负责改写和建议，不决定下载 URL；景点必须引用资料中的 ID，来源／署名／照片由程序组装，防止虚构引用。开放时间与票价不作为实时保证。资料不足时允许美食、路线、配图暂缺，不用常识补成伪造来源。

## 内容与缓存

保留五城离线内容作为初始包。共享 DestinationGuide 将 photo 改为可选，并增加 generatedAt/model 元数据；静态目录仍强制原有五城完整条件，独立单城运行时校验允许空美食、空玩法与缺图。UI 用 firstOrNull 读取路线并展示空态。每座城市读取顺序为有效磁盘缓存、初始包、尚未获取。只有完成的正文可缓存，图片只有下载并解码成功才显示，失败仅影响图片。城市内容和图片放 App 私有文件目录，通过临时文件完整写入后原子替换；旧缓存只在新内容有效时更新。

职责：CtripGuideSource 返回已核验城市及取材数据；DeepSeekGuideGenerator 仅根据该数据生成结构化正文；GuideRepository 管理单城市缓存、尝试记录与生成流程；AndroidGuideStore 实现私有文件与图片存储；DeepSeekSettings 用 Keystore 保存凭证；独立 DestinationViewModel 管理当前城市状态与取消，不改变查票 ViewModel 生命周期。

模型请求只在首次进入未尝试城市或显式更新／重试时触发；有效缓存命中时不请求模型。首次开始前持久记录已尝试状态，失败、取消或进程退出后再次进入仅提供显式重试，避免自动重发。离开 App 取消客户端网络任务；请求发送后服务商可能仍执行并计费，不能保证远端取消或恰好计费一次。无网络／模型自动重试，不承诺无缓存失败场景绝不再次计费。并发点击合并，切换城市时取消上一城市请求，使用请求代号防止晚到响应覆盖新城市。

采集与模型网络分用客户端：只有固定 DeepSeek 域名请求带 Authorization，网页／照片请求没有密钥。采集仅 HTTPS 携程网页和 c-ctrip 图片域名，校验重定向目标、响应体大小及超时。对解析失败、401、402、429、超时、截断响应和 JSON 无效给出可理解的错误；不回显服务端原始错误或请求头。

## 界面与配置

所有有票城市均可进入了解目的地，同时保留直接查看车次。沿用景点／美食／玩法／贴士四分页和阅读位置。缺内容时展示获取／整理中的明确阶段，失败可重试；已有内容时更新失败继续显示旧内容。资料来源区标识 DeepSeek 整理、生成日期和实际出处。照片或某栏目不足时显示简洁空态。

筛选页增加“目的地内容设置”入口，展示 DeepSeek V4.1 Flash 默认模型、密钥是否已配置；密钥输入掩码、仅内存编辑、不用 rememberSaveable、Android Keystore AES-GCM 加密后存本地，不回显已有密钥。保存空输入保留已有配置，显式移除才删除。解密失败视为需要重新配置，不覆盖旧密文。配置完成后新城市自动获取；首次未配置时提供设置入口。个人提供的 Key 通过隐藏输入在真机配置，不构建进 APK。

## 验证与交付

基线 `46205e3`，功能分支 `codex/v0.4.0`，本次前置源码备份为 `.verification-private/v0.4.0/deepseek/source-before.tar`。保持版本 0.4.0/code 8。本地实现与安装，不公开推送包含个人用照片的历史。

单元测试覆盖城市归属校验、网页字段缺失、模型错误与伪造 ID、无效/截断 JSON、缓存读写与失败保留、请求次数和密钥不进入采集。模拟器验证无配置、设置、新城市生成／重试、四分页、旧内容更新失败与缓存复用。最多选少量新城市执行真实生成验证，确认照片与来源后保存无密钥证据。备份真机旧 APK 与筛选设置，覆盖安装后比对包哈希及设置；至少验证一个新城市与重启后缓存读取。代码用反向提交回滚，真机使用备份 APK `adb install -r` 保留数据回滚。
