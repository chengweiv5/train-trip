## 交互

保留冰蓝配色、四分页和查票入口。取消介绍页汇总图库，图片紧跟各自景点/美食名称。零张不占位；一张无页码；二至三张在图右上角显示 `1/3` 等页码，可横滑。来源随当前图切换；点击进入该条目的大图相册，关闭时保留当前图片。图库滑动不得切换外层内容分页。只保留「更新目的地介绍」一个更新入口。

## 归属与限额

照片增加可选 subject（kind 为 place/food，name 为条目名称），由经核验的来源代码赋值，模型不生成图片 URL 或归属。城市由所属 guide 限定；不能用易复用的 p1 等顺序 ID 作为跨更新身份。相同城市、类型和名称/明确括号别名才能保留归属，多条匹配时舍弃。旧图仅在完整说明「当前城市 · 当前条目名」能唯一匹配时采用；泛城市封面、其他城市或已删除条目的图不进入新相册。

数量按成功保存的不同照片计算：每条目最多 3 张，城市下景点与美食合计最多 100 张。相同远端 URL/资源去重，不能跨条目重复使用同一图片凑数。已有可用图片优先保留，先给无图条目分配第 1 张，再按正文顺序分配第 2/3 张；到 100 张停止。失败下载不占名额。当前介绍仍保持 1–5 个景点、0–6 种美食，100 是总量保护上限，不自动扩充条目数量。

## 全量更新

先原子保存新正文及仍与新条目对应的可用旧图，再对零张图的条目补图；已有 1 或 2 张也不为了补满 3 张再次检索。不可用本地文件（缺失、为空、无法解码）按缺图处理。一个城市部分条目有图不妨碍其余条目补图。新增图片逐张原子提交，取消或失败保留已提交的文字和图片；离开/重启仅读缓存。

## 模块边界

- `GuidePhotoPolicy` 统一归属解析、去重、3/100 上限和缺图条目筛选，供来源、持久化和界面使用。老 JSON 可读，新字段可缺省。
- Ctrip 来源只读取匹配景点页，经城市/地点 ID 校验后赋予 subject，移除城市封面兜底。美食无法从景点页核实则不借用餐馆环境图片。
- Tavily 为缺图的景点/美食做定向查询，核对图说明中的城市与条目名；食品采用美食检索，图片说明必须明确是该食品。根级搜索图片也支持 food，但不能缺城市/食品归属。每个缺图条目最多一次付费备用查询，不重复同一请求。已有可用图的条目不发图片请求。
- 每条目候选最多 6 张、全城市候选最多 200 张用于失败替补；成功存储仍受 3/100 限制。主源无论给到 1、2 或 3 个候选都先尝试下载；无候选或全部失败才请求该条目备用来源。备用阶段只能处理仍零张的条目，每次更新同条目仅查询一次。
- Android store 在下载前和逐张提交时执行限额，持久化校验防止绕过。离线管理覆盖全部图片，沿用共享文件保护及取消清理。
- Compose 每条目调用复用相册组件，互不干扰页码；source 与大图关联当前照片。记录 schema 不变，新增照片字段兼容旧记录。
