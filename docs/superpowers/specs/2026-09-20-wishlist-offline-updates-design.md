# 想去清单、离线内容与版本更新设计

日期：2026-09-20。状态：用户已确认 A 方案及详细交互稿，开始实现。

## 目标与范围

在现有清爽蓝白界面上，增加常用城市收藏、管理本机目的地资料、查看正式版本更新。用户可以积累目的地，再确认日期查票；不增加服务器、账号、云同步、通知推送或后台定时任务。

沿用查询与 12306 App 的边界：本应用查余票、介绍目的地，购买在 12306 App 完成。本次不修改车次选择、席别、排序刷新对齐和已有服务配置方式。

## 设计产物

- 可编辑源：`design/train-trip-v0.5.0-navigation-options.pen`，保留 A/B 对比，并新增 D01–D23 详细画板。
- 评审入口：`design/reference/v0.5.0-detailed/index.html`。
- 版本号、容量、日期、城市和车票信息均为设计示例，不是真实联网结果。
- 状态规格画板将同一页面的互斥状态并列展示；实际 App 一次只显示当前状态。

## 导航与返回

底栏只有「查票」「想去」，文字与图标同时呈现，当前项使用主蓝色。只在两个根页面显示底栏，切换保留各自输入、列表和滚动位置。当前 Tab 再次点击不清空内容、不触发联网。

结果、城市介绍、查询条件、设置及其子页隐藏底栏。返回逐层回到实际入口，保留父页状态，不统一返回查票或结果页。系统返回与顶部返回相同。根页面系统返回沿用现有退出行为，不通过返回键反复切换 Tab。

「想去」右上角为「添加城市」。查询首页的设置入口保留，设置中增加「离线内容」「关于与更新」。不增加第三个底部栏目。

## 想去清单

### 数据与排序

使用现有城市目录中的稳定城市 ID，保存名称、省份和收藏时间；同城车站不分别收藏。同一城市最多一条，默认按收藏时间倒序，同批新增按目录顺序稳定排列。单次本地原子写入成功后刷新所有星标和数量。

收藏只保存城市，不保存某次余票、票价、席别或行程作为当前信息，不自动调用搜索或模型。卡片可展示本地已有的城市一句话与资料状态；无资料时显示「先留在清单里，下次再了解」。状态区分「介绍可离线查看」「仅文字可离线查看」「介绍尚未下载」「内置介绍」，图片失败不妨碍正文阅读。

列表载入失败显示「想去清单暂时无法读取」及重试，不伪装成空清单、不覆盖现存数据。首次空清单提供「添加想去城市」。卡片正文或「了解目的地」打开介绍，「查车票」打开单城条件草稿；星标的 48dp 独立点击区域只切换收藏，不触发卡片导航。

### 添加城市

从本地现有城市目录搜索名称、省份和拼音，按省分组。支持多选；已有项显示「已添加」且不重复加入。搜索不会丢失已选项；底部显示「添加 N 个城市」。未选任何城市时禁用，保存中禁用重复提交；成功后返回清单并展示新增项。

进入添加页创建临时选择草稿，返回放弃草稿，不改变已有收藏。失败保留已选项，显示「城市尚未添加，请重试」。没有搜索结果可清空搜索。键盘出现时底部操作避让输入法，列表可滚动；确认操作关闭键盘后反馈保存结果。

### 取消与撤销

清单、结果卡和城市介绍的星标共享收藏状态。点击已收藏星标取消，无额外确认框；成功后显示「已取消想去『城市』」与「撤销」。提示不遮住底栏，默认显示 5 秒，并遵循系统无障碍超时设置。

取消收藏只删除收藏记录，保留介绍和图片。撤销恢复原收藏时间和原排序位置。每次提示对应最近一次取消；多次快速操作顺序处理，只撤销提示所示城市。写入失败保留原状态并显示重试提示，不能先显示成功。撤销失败仍保留重试入口直到提示关闭；关闭后仍可从添加页重新收藏。

### 从想去查票

点击「查车票」创建独立查询条件草稿：目的地固定为该城市，出发地、席别、人数、时段、最长车程使用当前有效条件。日期沿用仍有效的值；已过期则回到现有默认有效日期范围。页面明确显示城市与日期，由用户点击查询后才联网。

这个草稿不改变首页的目的地范围或其他首页输入。返回清单丢弃未提交草稿。提交后复用现有查询管道，结果只包含该城市，保留「修改条件」入口；无票、部分失败和查询失败沿用现有反馈，不把已收藏解释为有票。查询结果再进入介绍或车次时仍保留这条返回链。再次打开单城草稿从首页当前条件初始化，不持久记忆每个城市的查询条件。

## 离线介绍与管理

### 页面与来源

设置 → 离线内容，显示已下载城市数、实际磁盘占用、各城市更新时间和「更新介绍」「删除」。点击城市行阅读介绍。正文与本机图片可离线查看，外链原文需联网。仅正文保存成功时明确标记「仅文字可离线查看」，图片用占位，不能声称图片已离线。

内置资料单独说明，不计入可清理空间、没有删除按钮。下载版被删除后，若该城市有内置介绍就回退内置版本，否则显示暂无本地介绍。磁盘统计包括该城市可识别的下载正文、图片及待清理残留；不含 APK 内置资源、收藏或密钥。

### 获取与更新

本版采用明确的手动整理入口：没有本地或内置介绍时先显示空态，用户点击「整理目的地介绍」后才调用 Tavily / DeepSeek；打开收藏、进入介绍和再次打开已清理城市均不自动下载。这一规则统一应用于从结果和清单进入介绍。

未配置服务时显示「请先配置 DeepSeek 和 Tavily，再整理介绍」，进入设置返回后保留城市上下文，但不自动开始。继续沿用现有国内来源、简体中文过滤、原文链接与图片署名规则；不收录繁体来源，不为收藏重新引入海外图源。

整理前保留用量提示，处理中防止同城重复请求，允许返回；任务绑定应用内 ViewModel 生命周期，退出应用不承诺后台完成。首次在正文提交前失败保留空态与重试；更新在正文提交前失败保留旧正文、图片与时间，错误提示与「重试更新」同时显示。

以新正文通过校验并原子持久化为一次更新的提交点。提交前失败或取消保留旧版本；提交后图片下载失败或取消属于部分成功，保留新正文与其更新时间，显示「介绍已更新，图片未保存」，不显示“更新失败”或混用旧版图片。无图片来源的介绍直接作为文字版完成。图片使用本次版本的临时文件，成功后再与正文关联；旧图在新正文提交后从展示引用中移除并清理，失败残留仍计入可清理空间。

相同城市任务串行，用户清理时取消在途更新并使过期回调失效，防止删除后文件又被写回。为更新生成的临时文件失败或取消后清理；取消发生于提交后时，正文已保存的事实保持可见。

### 删除

点击删除弹出确认框：城市、可释放容量、删除介绍和图片、保留收藏与服务设置、不会自动重新整理。取消直接返回，确认后显示处理中并禁用重复提交。确认时容量重新读取，页面容量只是估算。

成功后移除该下载条目、刷新总量，并同步清单和已打开介绍页的状态，清除该城市内存缓存与本地图片引用，显示内置回退或空态。「已清理」和「整理曾失败」不能混用；两者都需用户主动重新整理。

部分文件删除失败：按剩余文件重新统计，不报告全部空间已释放，显示「部分文件未能清理，可重试」。如果正文已删除则不继续显示其旧内存副本，残留图片保留为可再次清理的条目。内置资料始终可读。删除不提供撤销，用户确认前已知后果；重新整理不保证还原原内容。

## 关于与更新

应用名称、当前版本来自安装包。提供「检查更新」「更新说明」「GitHub 项目」。只有用户点击检查才请求 GitHub 正式 Release，无后台自动检查、无自建服务、无登录和模型调用。

| 状态 | 主文案 | 操作 |
| --- | --- | --- |
| 尚未检查 | 尚未检查更新 | 检查更新 |
| 请求中 | 正在检查更新 | 检查中，禁用重复请求 |
| 远端版本更高 | 发现新版本 x.y.z、短更新摘要 | 前往 GitHub 下载 |
| 成功且远端不高于本机 | 已是最新正式版、检查时间 | 再次检查 |
| 网络、限流、空结果或数据错误 | 暂时无法检查更新 | 重新检查 |

读取当前仓库 `chengweiv5/train-trip` 的 Release 列表，过滤草稿与预发布，再按数字语义版本选择最高稳定版本，不依赖可人工修改的 Latest 标记。按 GitHub 分页完整读取稳定候选；任一页失败都按检查失败处理。当前格式为稳定的 vMAJOR.MINOR.PATCH；无法解析的候选跳过，无可解析稳定候选时按检查失败处理。

新版本附件必须包含 `train-trip-v{版本号}-release.apk` 和同名 `.sha256` 文件才显示下载操作；缺少时显示「新版本暂未提供完整安装包」，保留前往发布说明入口。这是发布资产是否齐备的检查，APK 签名真伪最终仍由系统安装时校验。

检查请求超时显示失败，离开页面可取消请求。成功结果仅在本次页面会话内保留并标示检查时间；再次请求失败时显示失败，可保留上次成功时间但不能显示为当前“最新”。链接只打开当前仓库的 HTTPS 项目或 Release 页面。页面打开失败给出重试和复制发布链接入口；不静默下载、申请安装权限或自动安装。

更新说明默认打开本仓库的 Release 列表，不按本地版本号拼接未经确认的标签页；本次检查成功且返回的 Release 与当前安装版本一致时，打开该 Release 的实际地址。未检查、检查失败、开发版本尚未发布或查得版本不同，均保持发布列表入口。发现更新后的主操作仍指向已查得的新版本 Release。用户在浏览器下载正式 APK，系统负责确认安装。返回应用不假定安装成功，版本仍以安装包值为准。

## 实现边界（供确认后规划）

以下是职责划分，不要求提前抽象通用框架。

| 单元 | 输入与输出 | 依赖和约束 |
| --- | --- | --- |
| 收藏本地存储 | 城市 ID 的添加、移除、撤销、有序列表与错误 | 本地目录；原子写入；无网络 |
| 导航与查询草稿 | 入口上下文、单城条件、返回栈 | 复用现有查询模型，不覆盖首页条件 |
| 介绍存储与任务 | 缓存清单、磁盘大小、删除/更新结果、状态 | 扩展 AndroidGuideStore；处理正文、图片、内存和在途写入一致性 |
| 更新查询 | 当前版本 → 未检查/检查中/有更新/最新/失败 | GitHub 正式 Release；与模型和搜索配置无关 |

现有 `AndroidGuideStore` 按城市保存 JSON、图片和 attempted 标记，目前没有删除接口；`GuideRepository.cached` 包含内置回退。`DestinationViewModel.open` 目前可能首次自动整理，本设计改为明确手动整理；实现时要覆盖这一迁移，不能仅删除 attempted 标记。`AppViewModel` 当前集中管理查询条件，要为单城草稿保留入口和独立条件，不要求重写全应用导航。

收藏是新增数据，不迁移密钥。已有下载介绍通过现有存储扫描进入管理页；旧 attempted 标记兼容读取，手动整理规则生效后不再用于自动请求。写入新状态需可容忍旧版本已有文件及单城市损坏，不批量覆盖全部缓存。用户清理应用数据或卸载会丢失本机内容，页面保留“想去清单保存在本机”的说明。

## 正式版发布约束

延续已发布生产签名，递增 versionCode 与语义版本；签名材料、密码、DeepSeek/Tavily Key 不进入仓库、日志、APK 或 Release 附件。构建 Release，确认 debuggable=false、签名有效、包名兼容。没有 Key 的新安装也能查票、收藏、管理内置资料和检查更新，只在整理新介绍时提示配置。

发布前运行适用单元测试、lintRelease、assembleRelease；验证无配置新安装及从现有正式版覆盖升级，确认收藏、缓存、设置保留。APK 检查私有配置和凭据，生成 SHA256；上传正式 APK 和校验文件后重新下载核对散列。签名或代码验证失败不能发布 Debug 作为正式版替代品。

签名私钥按现有宿主机私有目录管理，发布前验证备份可读；不在设计中加入云端托管要求。遇到不同签名旧 Debug 安装，只解释无法覆盖，不自动卸载或清除数据。发布问题保留上一正式版下载，代码用后续更高 versionCode 修复；降低版本不是可靠的数据回滚方式。

## 布局、可访问性与验收

沿用白底卡片、浅灰页面、蓝色主按钮，红色只用于确认删除；正文与管理操作居左。标准 390dp，额外设计 320dp / 1.3 倍字体代表页。长标题和说明允许换行；正文区域滚动，底栏和底部主操作避让系统手势区、输入法。点击区域至少 48dp，星标有“加入想去/取消想去”语义，选中状态不只靠颜色，TalkBack 宣告新增、删除与错误。

设计验收：可编辑源保存后独立回读；可见节点裁切、同级重叠、文字及示例容量一致；原生渲染和 OCR；浏览器评审入口可用。设计验收不等于 Android 验证。

实现验收覆盖：收藏去重/跨入口同步/重启保留/撤销顺序/读写失败；单城查询不污染首页且返回正确；无 Key / 无网时不调用模型；内置与下载区分；删除与更新竞态、部分删除及损坏文件；旧内容保留；语义版本比较、预发布过滤、限流/超时/缺附件；320dp、大字体、键盘和 TalkBack；正式升级保留数据与密钥无泄露。
