# 结果页排序与刷新两端对称

用户反馈上一版排序文字过于靠左，要求左侧适当缩进，与右侧刷新文字保持视觉对称。本次是已授权布局调整的修正。

上版以排序文字与页面标题对齐为验收标准，遗漏了刷新 TextButton 自带内边距。旧截图中行边界为 x=55..1018，排序文字距左边界 0px，刷新文字距右边界 39px，实际不对称。

采用两个按钮共用 `PaddingValues(horizontal=16.dp, vertical=12.dp)`，保留页面 20dp 外边距，使两端文字均位于距屏幕边缘 36dp 的位置。两个按钮都显式保留至少 48dp 高度；排序继续占据剩余宽度、文字 Start 对齐，刷新随内容宽度布局。16dp 水平内边距也让刷新内容宽度超过默认最小按钮宽度，避免最小宽度补白造成两端间距不同。

沿用刷新默认间距只给排序补固定值容易受默认最小宽度、字体变化影响；将两个按钮强制等宽会压缩较长排序文案。这两种方式均不采用。

范围仅 ResultsScreen.kt 的操作行。两种排序文案、切换回调、刷新回调与查询中禁用条件保持不变。不新增图标、容器、数据逻辑或测试入口；窄屏或较大字体允许文字换行和按钮增长。目的地介绍页不在本次修改范围内。

验收：assembleDebug 与 lintDebug 通过；专用模拟器 390dp、320dp 下测量左右文字距行外边界的留白相等（像素取整误差最多 1px），两种排序状态都测量，文字垂直居中、无裁剪重叠，点击区域至少 48dp。通过实际点击检查排序切换；不调用内容生成服务。真机后台保留数据覆盖安装，回读 APK 哈希及配置/缓存文件哈希，不打断前台应用。

保留版本 0.4.0 / 8，个人版本仅在功能分支本地提交。源码及旧安装包备份在 `.verification-private/v0.4.0/results-action-symmetry/`。回滚可用 before.apk 覆盖安装，不卸载或清数据。
