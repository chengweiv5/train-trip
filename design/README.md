# Train Trip V1 UI 设计

2026-09-18 完成首版可编辑 UI 设计。源文件为 [train-trip-v1.pen](train-trip-v1.pen)，使用 Pencil 打开与编辑。

本目录保存可编辑 UI 设计稿和交互说明。Android 首版已实现，运行验证见项目 README。画板中的日期、城市、车次、票数及查询时间均为设计示例，不代表实时余票。

## 视觉与实现基准

- 手机页面以 412 逻辑单位宽度设计，边距 20，卡片圆角 16–22。
- 中文字体 Noto Sans SC；标题 28，正文 14–16，辅助信息 12–13。Android 用 sp 并允许字体放大。
- 主按钮高 56，交互控件目标点击区域至少 48dp；列表行和卡片整体可点击。
- 页面保留顶部 62、底部 28 的安全区示意。实现需使用系统实际 Insets，不硬编码设计值。
- 详情页购票操作在实现时固定于导航安全区上方，车次列表独立滚动。
- 目标设备为 Huawei Mate 60 Pro / HarmonyOS 4.2.0，计划 Kotlin + Jetpack Compose Android APK。

## 交互约定

1. 出发地默认北京，合并同城车站；首版只查成人、直达、去程。默认 1 人，席别和时长不限，包括无座。
2. 日期或筛选弹层点“完成”应用；关闭弹层保留原值。日期两端包含，时段按所选每一天的北京时间生效。
   时段两端在一个窗口中直接滚轮选择，开始包含、结束不包含；00:00–24:00 表示全天。窗口只修改草稿，滚轮停止后才能应用，重建恢复草稿。窄屏或大字体时内容可滚动，底部取消/完成保持可达。
3. 城市按最短车程排序，可切换车次数最多；详情默认出发时间升序。返回保留筛选与列表位置。
4. 查询进度与结果分开保存。停止查询保留已查结果；继续只补未完成部分。进度按已处理查询项 / 总项展示，成功、失败与未开售分别计数。未核实全国覆盖时显示“可能未覆盖全部目的地”。
5. 城市车次数按乘客上车日期和内部列车编号去重，同车次不同到达站保留为不同乘车选项。
6. 多人不能跨席别合计余票。“有”但未返回数量时，1 人可以匹配；多人单独标记数量待确认，不计入确定满足人数的结果。
7. 候补、无票、未提供席别、未开售、查询失败和取消各自显示；不能统一处理成无票。
8. 前往 12306 前重新核验选中车次和席别。数量不足取消选择；失败保留旧时间并提供重试和手动查入口。未验证的跳转不能声称已预填条件。
9. 跨日到达保留 +1/+2 天；不根据时刻先后误算历时。购票、登录和支付在 12306 完成。

## 首版验证记录（2026-09-18）

- Pencil MCP 回读：648 个可见节点、293 个文字节点；没有空名称或空文字，没有未完成占位画板。
- 结构与坐标检查：未发现裁切、顶层画板相交或同级图层相交，重叠检查容差 0.5 逻辑像素；35 个组件实例均可解析。
- 最终视觉检查：三个主页面、筛选与日期面板、九种状态及交互说明均已通过 Pencil 渲染检查。
- 本机 macOS Vision 对 7 张最终参考图完成中英文 OCR，识别出 293 段文字。OCR 中图标和少量细字有误识别，已结合可编辑原文与渲染画面复核；不把 OCR 当作逐字无误的证明。
- 颜色对比度：正文/底色 11.25:1，辅助文字/底色 4.72:1，按钮白字/深绿 7.57:1，深绿/浅绿 6.41:1，警示文字/背景 5.66:1。
- 设计文件保存后通过文件元数据和 Pencil 当前文档回读确认。没有进行真机安装、字体放大、返回手势或真实点击链路测试，这些属于实现阶段验收。

结构结果见 [validation/layout.json](validation/layout.json)，OCR 原始结果见 [validation/ocr.json](validation/ocr.json)。[reference](reference) 内的 JPEG 是最终开发对照图，不替代可编辑源文件。

## 保留与回滚

原始空白画板以隐藏节点 `h0pju`（“备份 · 原始空白画板”）保留在源文件中。可在 Pencil 中将它启用并复制到新文档，恢复原空白画板；现有设计不必删除。当前界面修复在功能分支 `codex/ui-polish`，实现和对应设计稿同步管理。每轮修改前的备份及回滚方法见对应验收记录。
