## 根因与修复

旧流程直接用本次生成的正文替换缓存，图片只关联到新列表仍存在的条目。当新检索未返回广府古城时，景点被覆盖，随后的图片清理也可能删除旧图。已在实际 ViewModel → repository → Android store 路径稳定复现：旧缓存含广府古城和博物馆，刷新只返回博物馆，旧版保存后仅剩博物馆。

现在 repository 在首次保存前合并缓存：旧条目保持顺序、名称和 ID；相同条目更新正文；新条目追加。匹配先比较标准化名称，再使用双向唯一的括号别名；歧义不覆盖。新生成的 ID 映射到合并后 ID，玩法引用和照片归属随之修正。来源按 URL 合并，新核对日期优先；无新玩法保留旧玩法。

单次生成仍最多 5 景点 / 6 美食 / 10 来源，累计缓存放开这些条目上限。图片仍最多每条目 3 张、每城市 100 张，旧可用图片优先保留，只对零图条目补图。缓存正文读写采用同一 16 MiB 保护限额，超限在替换旧文件前失败。
