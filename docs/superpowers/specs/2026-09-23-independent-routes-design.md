# 玩法独立参考规则

用户已明确的最终规则（2026-09-23）：玩法与景点列表独立；不同天数的不同玩法可以来自不同文章；同一条玩法内所有天必须来自同一篇攻略，不能跨文章拼接多日安排。

每天新增独立地点名 stops，旧 experienceIds 仅作为旧缓存兼容读取。地点可以不在景点列表中，不受景点/美食各累计 10 项限制。合并缓存、截断景点前将旧路线转换成独立名称。UI 使用名称，旧 ID 缺失时只展示已有安排，避免崩溃。

允许正整数 N 天，每个天数保留一条完整玩法，单次及累计最多 3 种，按天数从短到长优先保留。模型根据同一篇攻略整理多日参考，不要求逐字摘录、名称包含于 quote、顺序偏移校验，也不比较玩法与景点来源。保留来源归属校验、有效 URL、天数与 schedule 条数、非空文字等基本检查。旧离线编辑内容无逐条来源时仍能读取。

豆包搜索民间攻略，增加多日查询；资料不足可以缺省某种天数。补救最多一次，不把已生成介绍置空。景点和美食原文筛选、简体中文、图片规则保持现状。

验收：景点外地点、不同玩法不同来源、同一玩法混合来源拒绝、3 天及更长格式、满 10 景点后玩法保留、Gson 旧缓存读取；真实 API 与手机更新和冷启动。安装保持配置、收藏、图片，不清其他城市，不覆盖 v0.9.0 已发布包。
