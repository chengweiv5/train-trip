# 豆包搜索替换方案

用户已明确要求使用已验证可用的豆包搜索，DeepSeek 继续按原文整理；景点和美食单次及累计均最多 10 项。

采用独立的豆包 Custom API 适配器替换 Tavily 网页及图片搜索。调用 `https://open.feedcoopapi.com/search_api/web_search`，Bearer 密钥仅发送该搜索端点，不跟随重定向。网页按城市分别搜索景点、美食，各取最多 5 篇可信来源，以原文 Content 为证据，禁用只依赖 Snippet 的正文生成。保留受信国内来源、简体中文、城市归属、连续引用校验。

缺图条目按城市名和条目名调用 `SearchType=image`，每次最多 5 个候选。结果标题或图片说明必须同时支持城市与条目；排除装饰图、餐馆环境图及不受信网页来源。允许官方搜索签名 CDN 的精确主机格式，下载不携带 API Key，保留来源网页及豆包检索署名。已有可用图片优先，继续每条目 3 张；豆包为首选图片源，携程为缺图后备。

设置入口显示“豆包搜索”，保持现有布局，独立使用 Android Keystore 加密保存新密钥，不迁移或发送 Tavily 密钥。原缓存与 DeepSeek 配置保留。真实密钥只用于本机验证，通过 stdin 交给验证程序，不进入源码、命令行、APK、日志。

验证包括 HTTP 参数与业务错误、域名过滤、取消、重定向、图片归属、密钥独立存储及 Android 设置流程；至少一座城市真实执行豆包搜索 → DeepSeek 整理 → 豆包图片查询与下载。功能分支提交，不在本轮发布或安装到手机。
