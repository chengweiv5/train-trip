## 结论与当前门禁

**已实现并离线验证订单适配和原生操作流程，但尚不能宣称真实候补下单全链路打通。**

- 同会话重新查询选中车次、候补初始化、服务端截止选项、最终用户授权、单次 `confirmHB`、队列/订单列表查询与精确归属恢复已经接线。
- 官方风控运行时是当前真实阻塞：宿主网络对页面实际引用的 `ua_rds.js` 返回 HTTP 200，但正文是 `resultStatus=43007` 的失败 JSON，不是运行时脚本。按官方页面时间参数、User-Agent 和 Referer 重试仍失败。
- 独立模拟器通过同一验证组件实测 `RUNTIME_UNAVAILABLE`。失败退出测试通过不代表风控验证成功。运行时缺失时不会启用最终提交，未伪造 `encryptedData`、滑块 session 或签名。
- 没有使用真实账号初始化或提交订单，没有取消/支付。手机网络上的官方验证、真实候补响应与真实订单查回仍需用户参与。
- 官方脚本未提供经真实样例验证的逐项拒绝归因契约；生产适配暂不生成 `Restricted`，不将含糊文案映射到车次，不自动排除后盲目重发。原状态机的精确拒绝自动续提能力仍有测试，但**不能据此声称生产自动排除已接通**。

## 本轮实现

### 初始化

1. 刷新账号与乘车人，核对实际乘客引用和票种。
2. 使用相同内存会话读取 `leftTicket/init`，动态获得查询路由；重新查询每个准确日期/区间，匹配内部车次号和席别。
3. 已有票、限制标记、未知数据、车次时刻变动均停止，不悄悄删除需求。
4. 一次提交完整 `secretList` 给 `afterNate/submitOrderRequest`，再读取 `passengerInitApi`。初始化不是 `confirmHB`，不可把它的成功当作订单创建。
5. 核对服务端返回完整集合与用户选择完全一致，保留用户顺序；乘客上限和截止选项来自本次响应，不硬编码全局上限。
6. 成人票以外、跨境或额外人证核验等未验证分支明确停止。

### 授权与提交

- 用户选择服务端返回的“开车前 N 分钟/小时/天”选项，完成官方安全验证后，仍需点击原生最终确认按钮。
- 仅在一个受限 WebView 中加载官方风控组件，不在 WebView 登录，不传入原生账号 Cookie、密码或乘车人；没有 JS bridge。仅允许组件所需 HTTPS 域名，禁止订单和登录路径、文件访问、任意导航、混合内容；TLS 错误取消。
- 验证凭据只存在内存，不进入 StateFlow、快照或日志；预览 180 秒有效、验证 90 秒有效，一次凭据只授权一次发送。
- 授权必须使用当前预览实际生成的完整请求（含请求 ID、授权时刻和查单匹配上下文），不能传入自行构造或删改的请求。发出一次提交后消费整个预览，不能复用相同证明生成新请求。
- 协调器先原子保存 pending attempt，再交给 Gateway；账号、需求、截止时间、请求 ID 绑定。POST 使用固定长度流模式避免缓冲请求透明重放，不自动重试。
- 当前页面主需求由初始化会话持有，`hbTrain`/`plans` 按当前官方页面的未选备选方案状态传空；多需求 `secretList` 已有合成契约测试，**仍待真实服务端对多需求的接受验证**。
- 无座、新增临客、自动支付、取消均未选入；不会隐性扩大用户订单范围。

### 查单与恢复

- 提交响应无论是成功标记、超时还是含糊错误，均进入查单；`flag=true` 不是订单号，队列 `status=-1` 也不能独立证明本次没下单。
- 查询 `afterNate/queryQueue`、`afterNateOrder/queryQueue`、`queryUnHonourHOrder`，后者最多 10 页；页面不完整/失败不确认为成功。
- 匹配账号、真实乘车人及票种/证件、完整日期/车次/区间/席别、截止时间和授权附近的创建时间。多个匹配、字段缺失、脱敏无法精确核对或空列表保留未决。
- 可持久化的数据新增非敏感订单匹配上下文：授权时间、公开车次标识。没有持久化 Cookie、查询 secret 或乘车人原始资料。
- 旧快照兼容读取，缺失匹配上下文时不冒认订单；恢复 pending 只查单，不重放。
- 创建时间窗口为保守的 180 秒；超过窗口的真实迟到订单可能需要官方人工核对，但不会用宽泛匹配把其他订单当成本轮成功。
