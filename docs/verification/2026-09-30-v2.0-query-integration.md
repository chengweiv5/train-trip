## 交付范围

开发验收阶段完成**原生候补查询/选择接入及恢复基础适配**，不是 v2.0 全量完成。验收时尚未 commit/push，随后用户单独授权“提交并推送”，交付按下方规则执行；未发布，版本仍为 1.0.0 / 15。只在隔离的无界面模拟器安装 debug 包，没有在连接的物理手机安装或操作。

- 底部“查票 / 候补 / 想去”，普通查票输入不被候补覆盖；想去可携目的地进入候补。
- 独立候补草稿持久化；已应用条件与结果绑定，编辑未查询的草稿不改变旧结果标题或查询错误。重试使用已应用快照。
- 两个城市/车站一体化选择器，取消不应用，换城市清空旧站；日期、时段、席别、车种、最长车程、排序、只看可加入均在条件页。
- 匿名查询读取 `houbu_train_flag` 和 `houbu_seat_limit`；按席别判断，不因二等受限而误删一等。没有已核验映射、无座、其他席别和未知状态不作为可选需求。
- 按准确日期/列车/实际起终站/席别去重；隐藏所选需求明确计数并可查看、移除；应用新的路线/日期/车站条件时清理不兼容项并告知。
- 官方查询日期范围来自当次初始化，不把查询日期范围当作订单组合上限。已取得范围后日期控件据此限制；首次未取得范围时查询前验证，失败保留官方范围供修正。
- 查询失败、未完成、尚未起售与真正空结果区分；退后台或切离候补暂停查询与后续候补提交，不取消订单。
- `AndroidWaitlistStore` 在 `noBackupFilesDir` 用 AtomicFile、fsync 和落盘回读；版本化任务快照损坏不能静默视为空任务。只存应用内身份引用，不存密码、Cookie 或加密乘客凭据。
- `WaitlistCoordinator.restore()` 在认证前只恢复并暂停显示，不发提交/查单，不把旧身份引用当成已登录。已保存进度接到原生页面；真实网关仍关闭。
- 四主题复用当前 Theme.kt，长段提示和卡片只用主题角色。分页面保存滚动状态，支持小屏大字。

以下仍待实现/核验：

1. 同一会话的真实登录、真实乘车人及平台能力/组合限制，确认页与生产提交、订单核对网关。
2. 精确拒绝归因的脱敏真实响应、返回原子性及部分入单差异；多订单、金额、支付期限和恢复流程完整 UI。
3. 选择清单目前保留于 ViewModel：切换页面、配置重建不丢失；进程死亡后保留的是查询条件及**已提交任务**快照，不是尚未提交的候选清单。不得宣称候选清单已跨进程恢复。
4. 当前 UI 状态覆盖不等同 17 屏全部运行验证；订单成功、自动续提等仍主要由 core 测试验证。

没有执行用户账号认证、读取真实乘客、提交或取消任何订单。
