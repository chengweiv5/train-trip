# “有”直接计入有票城市

用户明确要求：车次席别返回“有”表示大量余票，可直接计入有票城市。沿用 brainstorming / writing-plans 流程记录这项已授权的行为更改。

## 规则与边界

- 对应用支持的 1–20 人，“有”均满足席别余票条件；显示“有票”，原始值保留，count 仍为 null，不编造张数。
- 返回数字仍须同一车次、同一席别不少于人数，不跨车次或席别合并数量。
- 起售状态、停售时间、日期、时段、出发站、目的地和所选席别继续约束结果；“无”、候补、未起售、未知不计入有票。
- 城市总数、省份分组、详情席别和出发前再次核验共用 confirmedFor/confirmed 规则。重新核验仍实际查询；最新数字不足或无票时清除选择并禁止购票跳转。

## 实现选择

仅改判断会留下永不使用的待核验 API 和页面；虚构大量票的数字会损失源数据语义。采用统一 AVAILABLE 判断并移除仅服务于旧规则的数量待核验分流。SeatAvailability.label() 不再需要人数参数；Trip、aggregate、groupResults 及结果组件删除 uncertain 参数或分支。其余查询调度和解析逻辑保持现有行为。

筛选说明写明“返回‘有’直接视为有票；返回具体张数时需满足人数”，结果和详情统一显示“有票”。五城旅行资料不扩充。
