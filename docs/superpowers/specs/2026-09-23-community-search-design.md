# 民间攻略与图片搜索改进

用户要求：改善邯郸景点、美食图片覆盖，单独检索路线攻略；以民间网络内容为主，保留携程和马蜂窝。手机全部已下载城市缓存已按用户要求通过应用入口清理；只验证邯郸，其他城市待效果确认后统一生成。

## 采用方案

采用“分类查询 + 民间内容排序 + 缺项有界补查”。仅移除白名单仍会让搜索排名中的政府页面占用名额；无限增加查询会造成限流与延迟。因此选用四类主要查询：景点游记、美食体验、一日游、两日自由行。首轮定向检索携程、马蜂窝、穷游、什么值得买、新浪与小红书，每次网页取十条；景点或美食可用资料不足时追加一次不限站点的补查。政府及官媒不进入主要攻略语料；不把平台上的个人文章等同于官媒。保留简体中文、城市相关性和原文证据，按网址去重，每类每站最多两篇、每类最多六篇。

图搜使用原名称；无合格候选时再查一次稳定简称及实拍词，最多两次/条目。只去掉“景区、主题乐园”等通用尾缀，不把“龙湖公园步行街”误认为“龙湖公园”。景点的城市和条目归属来自标题或图片说明，不凭 query 强行认领；美食按完整菜名匹配，允许说明不含城市，并明确标注“菜品参考图”。图片来源网页允许公开民间网站；实际下载仍只允许已支持的图片域名和豆包图片 CDN。排除装饰图、地图和美食店面环境图片。

路线优先来自独立 routes 语料；其他检索类别的综合游记只要含明确行程也可使用，每天保存对应攻略 URL 和连续原文，所选景点在原文中出现并按原文顺序排列。只引用本次选出的景点，不添加交通、门票等编造事实。没有有效攻略时仍可为空，不能为达到数量伪造路线。UI 沿用现有玩法卡片，只加入“查看攻略原文”。

请求串行并保持最小间隔，HTTP 429 和业务 700429/rate_limit_exceeded 有限退避重试。美食、路线和个别图片检索失败不抹去已成功内容。保留景点/美食单次与累计各十项、每项三图、每城市一百图保护上限，保留其他城市收藏和配置。

## 验证与交付

以实测原始结果锁定回归：新浪游记不再被过滤、娲皇宫简称可匹配、步行街不能误配公园、菜品实拍与店面图区分、路线原文与顺序校验、限流重试及取消。跑 core 测试与 Android 编译/lint，使用同一生产链路重新生成邯郸，统计景点/美食/路线和实际可解码图片。手机保持其他城市零下载，仅在验证后安装并生成邯郸；不批量生成其他城市。

回滚：修改前源码归档位于 .verification-private/community-search/before.tar；原签名 APK 保留于 .verification-private/doubao-phone-install/。用户明确清除的缓存不自动恢复。

审阅补充：同篇原文只能提供城市上下文，图片自己的标题/说明仍须命中条目，不能认领多景点文章的任意图。路线源必须明确描述游览行程，普通景点列表不算；路线文档中的景点亦可进入推荐，但继续逐条核验连续原文。实测逐项记录候选、拒绝/下载失败及可解码数量，报告所有无图项。清理包括正文、路线、图片和内存引用，重启确认旧缓存不返回。必须等用户确认邯郸效果符合预期，才生成其他城市。
