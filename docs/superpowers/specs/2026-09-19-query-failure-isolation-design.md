# 查询失败不阻塞后续项目

## 已确认的需求

用户要求：某个日期/城市查询失败后，其余查询项目仍继续执行。此次修改针对查询调度；先前定位的未起售 `*` 解析错误继续作为单项失败保留，不在此修改中改变票态含义。

## 行为与边界

- SearchEngine 按现有顺序逐项查询，保持默认 1100 毫秒间隔，每项只请求一次。
- 返回 Failure、NotOnSale，或 query 抛出普通 Exception 时，都记录当前项结果并继续；取消异常原样抛出，不能被记录成失败或成功。
- 删除 Failure.stopSearch 和连续失败 3 次自动停止规则，避免数据源决定整个批次是否继续。
- 每项完成后更新进度；所有项目尝试完毕后 running=false、stopped=false、remainingCount=0。有失败仍 complete=false，成功结果、失败原因和“重试未成功项”保留。
- 手动停止、切后台及协程取消继续立即终止。初始化失败仍由 AppViewModel 提示，因为尚未建立查询计划/会话。
- 重试只请求未成功项，复用成功结果；不增加自动重试或并发。

## 方案选择

采用在 SearchEngine 边界隔离单项失败。仅删除提前 return 会遗留普通异常中断批次的路径；在每个数据源中分别实现隔离则易遗漏。统一边界便于验证并保留取消语义。

## 验证与交付

先运行失败回归：真实解析失败后仍尝试其余日期，连续三个失败后仍有成功项，抛异常后仍继续；校验失败计数、待查计数、停止标志和仅重试失败项。验证取消后后续项目不执行，默认请求间隔仍有效。

运行核心测试、Android APK/测试 APK 构建及 lint；模拟器离线验证失败后继续、错误查看和仅重试失败项。根据本任务此前“安装到真机”的交付要求，用相同签名将 0.2.1 / code 5 覆盖安装至 Mate 60 Pro；安装前备份 APK 与筛选偏好，安装后核对包哈希、版本、启动和偏好一致。
