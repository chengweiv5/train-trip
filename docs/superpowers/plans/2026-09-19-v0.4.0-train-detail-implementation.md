# v0.4.0 Train Detail Implementation Plan

> 后续调整：用户已确认移除复制车次入口，最新结果见 [移除复制入口验收](../../verification/2026-09-19-v0.4.0-remove-copy.md)。下文保留本轮调整之前的历史记录。

> **For agentic workers:** Execute inline in this session; the referenced superpowers execution skills are not installed. Steps use checkbox syntax for tracking. The user has authorized implementation.

**Goal:** Implement the approved seat-selection UI, manual city refresh, and direct Railway 12306 App launch.

**Architecture:** Keep navigation and selection in AppViewModel. Model refresh failures separately from cached successful results in SearchProgress so old tickets remain visible without falsely reporting completion. Put the native launcher and detail action components in focused files.

**Tech Stack:** Kotlin, Compose Material 3, coroutines, JUnit, Android instrumentation, Android minSdk 26 / targetSdk 36.

## Global Constraints

- Branch codex/v0.4.0 rebased onto origin/main d4f1013 before implementation; preserve the early-morning preset.
- No mandatory query, automatic copy, confirmation, website fallback, or automatic install when opening 12306.
- Package com.MobileTicket; discover its launcher via PackageManager, never hardcode an activity.
- Current-city refresh uses the applied query plan. Failures retain original successful data and timestamps, remain incomplete, and support retry.
- Selection clears when hidden by a filter or invalidated by a successful refresh; sorting and App return preserve it.
- 320dp / 1.3 font, safe insets, 48dp targets, accessible selected/disabled and feedback states.
- Source backup: .verification-private/v0.4.0/implementation/rebased-source.tar; baseline recorded beside it.
