# DeepSeek 目的地介绍验收

## 实现

手机直接读取携程公开目录、城市、景点与餐馆页，将已取资料提交到 DeepSeek 官方 API，再把通过校验的内容与成功解码的照片缓存到 App 私有目录。无自建服务；首版仅接入携程。已有五城资料继续离线可用，所有有票城市开放「了解目的地」。

默认模型使用账号模型列表实际返回的 `deepseek-flash`。用户所说的 DeepSeek V4.1 Flash 在界面以产品名展示。官方 `/models` 验证 HTTP 200；Responses 文档说明 `web_search` 等内置工具被忽略，故不依赖模型联网。

模型只能选择已取资料中的景点、菜品 ID；来源、照片、名称、地址由程序赋值。真实生成曾补充原文没有的菜品口味，最终实现改为使用来源明确列出的菜品与餐馆说明，不采用模型生成的菜品描述。游览时长、玩法为参考建议；无可靠资料时允许空美食、空路线或缺图。

缓存优先于初始包。首次开始前写入尝试记录；失败、取消、进程退出后只提供显式重试，不自动重复调用。更新失败保留旧内容。切城、离页、应用进入后台会取消任务，请求代号防止晚到结果覆盖新页面；服务商已接受的请求仍可能计费。

API Key 在掩码且禁止截图的设置弹窗输入，以 Android Keystore AES-GCM 加密后保存。采集客户端不携带密钥；只有固定 DeepSeek 域名收到 Authorization，模型请求不跟随重定向、无自动重试。配置修改不会替已离开的城市发起生成。

## 真实网络验证与限制

开发中已实际取得苏州目录、城市、拙政园与得月楼公开页面。首次全链路运行时，携程把请求重定向到 `verify.ctrip.com` 验证页；客户端停止，不请求挑战页面，也没有调用模型。此情况在 App 中明确提示网页验证，保留缓存并允许稍后重试，不作绕过。

使用本轮先前已取得的真实苏州页面快照，官方 DeepSeek 调用成功，得到苏州结构化介绍和真实来源/照片链接。这证明来源解析与模型链路可用，不等同于当前手机能够实时采集所有城市。最终生成器再次真实调用成功，得到 1 个景点、6 种菜品、1 条路线和实际照片链接，菜品描述均来自程序绑定的餐馆出处；内容与来源逐项检查通过。本轮共 2 次成功生成，未记录精确 token 用量。

城市未收录、归属不符、页面结构变化、验证页或网络失败都可能导致新城市暂时无法整理；不得把本次版本表述为覆盖全国且保证自动获取。
