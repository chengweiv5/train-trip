# v2.0 候补下单 · 当前评审稿

用户已明确核心行为为自动继续候补：筛选车次 → 选车次/席别 → 登录并选乘车人 → 一次开始 → 自动排除明确被拒绝的需求并提交剩余项 → 订单创建 / 候选全部失败。订单创建后立即停止自动提交，在 12306 支付。

每一轮将全部剩余需求放在同一次提交中。首轮 A+B+C，A 拒绝后 B+C，再拒绝 B 后 C。已去掉自行加入的自动分组和“后续候选”指标，运行页改为“最初选择 / 已排除 / 剩余需求”。超出官方单次组合限制时由用户先调整选择，不自动拆单。

全部筛选集中第 1 页。出发地、目的地各自采用与查票页出发地相同的整行入口：城市 + 同城各站/具体站名 + 箭头，点击后在同一面板选择城市与车站。已删除重复的独立“出发站 / 到达站”和“更多条件”容器。第 2 页通过“修改条件”返回第 1 页并回填原输入。独立筛选页和结果页日期快捷筛选已移除。

查询默认开启“只看可加入候补”，过滤所选席别中的灰色受限项；仍有符合条件的可候补席别时保留车次，否则隐藏整趟车。第 1 页的默认选中态已同步。该规则为设计约定，Android 功能尚未实现。
