### 正常会话是必要线索

首次直接请求网页引用的 `leftTicket/queryG` 得到 HTTP 302，指向官方错误页，没有票数据。先 GET 官方查询页并保留其自行设置的匿名会话 Cookie 后，同参数返回 200 JSON。验证中没有登录、读取用户浏览器 Cookie、下单或提交候补。

这说明当前会话初始化方法有效，不证明 Cookie 是唯一影响因素，也不证明获得了正式开发者 API 或服务稳定性保证。生产实现必须隔离票源适配层，并在协议变化时明确失败。

### 官方网页交叉核对

独立 in-app browser 正常输入北京、天津、2026-09-19 后显示 309 个查询行，按内部列车编号去重为 202，与随后 HTTP 响应一致。

- C2551：北京南 06:00 → 天津 06:30；二等座“有”。同一车次另有至滨海的行程，不能重复计为两趟车。
- K2601：网页硬座 9 张，随后 HTTP 响应 7 张；时间不同，库存变化正常，需保留每次查询时间。
- K7731：网页硬卧“候补”，API 原始席别字段为“无”。候补由余票和候补标记、限制及可用时间等组合渲染，不能只按一个字段猜测。对本 App 的有票筛选而言，两者都不算现票。
- K411：23:59 出发、次日 01:25 到达，历时 01:26，验证了跨日场景。
- 国庆样本中同时有可售、不可售、以及“列车运行图调整,暂停发售”的记录；仅检查车次列表存在或按钮文字会误报有票。

## 车站与城市归并

当前官方字典有 3,388 条车站记录、430 个城市 id，包含城市名称。北京归属下有 65 条记录；其中可能包含郊区、历史或非当日运营站，不能直接当成当日可上车站。

北京—天津一次城市查询实际返回 7 个北京出发站、9 个天津到达站，证明本样本支持同城扩展。例：天津、天津西、滨海、塘沽可按所属城市汇总为天津。

51 个城市名称没有对应的同名车站，不能简单地为每座城市猜一个同名站点。当前尚无经过验证的全国直达候选全集，所有站点暴力组合也未经请求成本和服务限制验证。

后续数据层的验收必须覆盖：出发地所选站点、直达列车的中途站、目的地同城别名、每日时刻表变化以及部分失败的覆盖提示。只有取得候选范围证明才能显示“全部城市已查完”。

## 下一阶段的技术决定

优先尝试 **手机直接通过正常匿名会话进行少量查询**，TicketSource 负责初始化、读取、字段校验和失败分类；先做单城市对的真机验证。该路线不需要部署服务端。

全国目的地发现单独解决：先验证城市代表站与同城覆盖、或使用完整时刻表构建直达候选，再设计有限并发与可取消的前台查询。此项没有完成前只能展示明确覆盖范围的试验结果，不能伪装为全国结果。

如果手机端正常查询不稳定，保留 WebView 或有明确契约的其他票源作为后续方案；本次尚未切换票源、付费或引入服务端。
